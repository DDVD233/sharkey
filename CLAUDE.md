# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Sharkey is a fork of Misskey: a decentralized, ActivityPub-based social media server (fediverse). It federates with Mastodon, Pixelfed, etc., and additionally implements the Mastodon client API. Upstream is hosted on GitLab (`activitypub.software/TransFem-org/Sharkey`), not GitHub — much of the lineage and many file headers reference `misskey-project`.

Branches: `stable` tracks releases (production), `develop` is where the next release is built. PRs target `develop`.

## Monorepo layout

pnpm workspace (pnpm 9.6, Node 22.11). Key packages under `packages/`:

- **backend** — Fastify + NestJS server. The bulk of the logic.
- **frontend** — main Vue 3 + Vite web client.
- **frontend-embed** / **frontend-shared** — embeddable client and shared frontend code.
- **misskey-js** — TypeScript API client/SDK; its types are partly autogenerated from the backend's `api.json`.
- **megalodon** — Mastodon-API compatibility layer (vendored fork).
- **sw** — service worker.
- **misskey-reversi**, **misskey-bubble-game** — game logic packages.

## Common commands

Run from the repo root unless noted. Most delegate to packages via `pnpm -r` or `pnpm --filter <pkg>`.

```bash
pnpm build                 # build-pre + build all packages + build-assets
pnpm dev                   # full dev: watches backend (swc), frontend (vite), sw (esbuild); auto-restarts
pnpm migrate               # run pending DB migrations (TypeORM)
pnpm revert                # revert last migration
pnpm start                 # run built backend (expects prior build + migrate)
pnpm lint                  # typecheck + eslint across all packages
```

### Building & restarting this instance (production)

This host defaults to Node 21, but the repo requires Node 22 (`pnpm` aborts with `ERR_PNPM_UNSUPPORTED_ENGINE` otherwise). Always select Node 22 before any `pnpm` command, and use the full `pnpm build` — it runs `build-assets`, which generates `boot.js`/`LANGS_VERSION`; building with swc alone leaves the client broken. The server runs under pm2 as `sharkey`.

```bash
export NVM_DIR=~/.nvm && source $NVM_DIR/nvm.sh && nvm use 22   # -> v22.x; do this first
pnpm build                 # full build incl. build-assets (NOT swc alone)
pm2 restart sharkey        # restart; pm2 logs sharkey to verify boot
```

No DB migration is needed unless entities/migrations changed (then `pnpm migrate` before restart).

Per-package work is faster than `-r`:

```bash
pnpm --filter backend lint        # = typecheck (tsc) + eslint, backend only
pnpm --filter frontend typecheck  # vue-tsc
pnpm --filter frontend test       # vitest
pnpm --filter misskey-js test
```

### Backend tests

Three suites: **unit** (`test/unit`), **single-server E2E** (`test/e2e`), **federation E2E** (`test-federation`). E2E and many unit tests need a real Postgres + Redis.

```bash
cp .config/test-example.yml .config/test.yml          # one-time setup
docker compose -f packages/backend/test/compose.yml up # DB + Redis for tests

pnpm --filter backend test                            # unit
pnpm --filter backend test:e2e                        # single-server E2E (builds first)

# run a single test file (pass path after --):
pnpm --filter backend test -- packages/backend/test/unit/activitypub.ts
pnpm --filter backend test:e2e -- packages/backend/test/e2e/nodeinfo.ts
```

Jest runs with `--experimental-vm-modules` (ESM). Frontend uses Vitest, not Jest.

### Regenerating the misskey-js API types

When backend endpoint definitions change in a way that should surface in the SDK:

```bash
pnpm build-misskey-js-with-types
```

This builds the backend, emits `api.json`, and regenerates `misskey-js` types from it.

## Configuration

Runtime config is YAML in `.config/`, loaded by `packages/backend/src/config.ts`:
`MISSKEY_CONFIG_YML` env var overrides the filename; otherwise `test.yml` when `NODE_ENV=test`, else `default.yml`. Env vars can override individual fields. Requires Postgres, Redis, and FFmpeg; Meilisearch is optional but needed for some search features/tests. Start from `.config/example.yml`.

## Backend architecture

The backend is **NestJS dependency injection on top of Fastify**, even though it doesn't use Nest's HTTP layer. Understand these three pieces before changing backend code:

- **DI modules**: `GlobalModule.ts` provides infra singletons (DB connection, Redis clients, config, meta). `CoreModule.ts` wires up the ~150 services in `src/core/`. `MainModule.ts` is the root. Injection tokens are `Symbol`s defined in `src/di-symbols.ts` (`DI.config`, `DI.db`, `DI.redis`, all the `*Repository` symbols, etc.) — inject repositories and infra via `@Inject(DI.x)`, inject services by class.

- **Services** (`src/core/`) hold all domain logic — one service per concern (`NoteCreateService`, `DriveService`, `ActivityPubService`, `UserFollowingService`, …). The `activitypub/` and `chart/` subdirectories group federation and metrics logic. Endpoints and queue processors are thin and delegate to services.

- **Boot/process model** (`src/boot/`): `entry.ts` → `master.ts` forks workers; a process runs the web server, the job queue worker, or both depending on config. `daemons/` are background loops. `queue/processors/` are BullMQ job handlers (account deletion, federation delivery, file cleanup, charts, etc.).

### API endpoints

Endpoints live in `src/server/api/endpoints/` (subfoldered by area: `admin/`, `notes/`, `users/`, `drive/`, …) and are registered in `endpoints.ts` / `EndpointsModule.ts`. Each endpoint file exports:

- `meta` — auth requirements (`requireCredential`), tags, rate `limit`, response schema (`res`), declared errors.
- `paramDef` — JSON-Schema for input (validated automatically).
- a default-exported `@Injectable()` class extending `Endpoint<typeof meta, typeof paramDef>` whose constructor calls `super(meta, paramDef, async (ps, me) => { ... })`.

The schemas drive validation, the OpenAPI doc (`server/api/openapi/`), and misskey-js type generation — keep them accurate. The Mastodon-compatible API is separate, under `src/server/api/mastodon/` backed by the `megalodon` package.

Other server entry points in `src/server/`: `ActivityPubServerService` (inbox/outbox/AP object serving), `FileServerService`, `NodeinfoServerService`, `WellKnownServerService`, `oauth/`, `web/`, and the WebSocket `stream/` API.

### Database

TypeORM. Entities in `src/models/` (e.g. `User.ts`, `Note.ts`), exposed as repositories via DI symbols. Migrations are TypeORM migrations under the backend; generate with `pnpm --filter backend migrate:generate` and run with `pnpm migrate`. Repositories are also wrapped by "pack" services that shape entities for API responses.

## Frontend architecture

Vue 3 + Vite (`packages/frontend/src/`). Notable pieces: `router.ts` / `router.definition.ts` (custom router), `pages/` and `components/`, `os.ts` (global OS-level UI API: dialogs, popups, API calls), `store.ts` + `preferences/` (state and synced user preferences), `stream.ts` (WebSocket streaming), `theme.ts`, and `aiscript/` (AiScript plugin runtime — Sharkey supports user plugins written in AiScript). Components/stories support Storybook (`pnpm --filter frontend build-storybook`).

## Conventions

- Source files carry SPDX license headers (`AGPL-3.0-only`). Preserve them; new files should include the same header block.
- Endpoint default exports intentionally disable `import/no-default-export` — follow the existing pattern rather than fighting the lint rule.
- Backend `lint` = typecheck **and** eslint; a green `eslint` alone does not mean types pass.
- When changing ActivityPub payloads, upstream asks that the change be reflected in misskey-hub's `ns.md` documentation.
